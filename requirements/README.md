# Dependency lock policy

These files are generated inputs to the `yt_final` 1.0.0 release process.
Never hand-edit a `*.lock` file.

The reviewed compiler is Python 3.11 with `pip==26.1.2` and
`pip-tools==7.6.0`. From the repository root, compile each input with:

```text
<canonical-absolute-python-3.11-path> -I -m piptools compile --allow-unsafe --generate-hashes --newline=LF --no-emit-index-url --no-emit-trusted-host --resolver=backtracking --strip-extras --output-file=requirements/build.lock requirements/build.in
<canonical-absolute-python-3.11-path> -I -m piptools compile --allow-unsafe --generate-hashes --newline=LF --no-emit-index-url --no-emit-trusted-host --resolver=backtracking --strip-extras --output-file=requirements/dev.lock requirements/dev.in
<canonical-absolute-python-3.11-path> -I -m piptools compile --allow-unsafe --generate-hashes --newline=LF --no-emit-index-url --no-emit-trusted-host --resolver=backtracking --strip-extras --output-file=requirements/release.lock requirements/release.in
<canonical-absolute-python-3.11-path> -I -m piptools compile --allow-unsafe --generate-hashes --newline=LF --no-emit-index-url --no-emit-trusted-host --resolver=backtracking --strip-extras --output-file=Final/approved-python.lock Final/requirements.txt
```

Replace the path token with the reviewed interpreter's literal canonical
absolute path; never substitute a bare command, relative path, shell alias, or
`PATH` lookup. Manual generation is not release evidence. The automated gates
run Python modules with `-I`, remove inherited `PYTHONHOME`, `PYTHONPATH`, and
`PIP_*` values, disable user-site packages, pip configuration, version checks,
and interactive input, and add pip's `--isolated` mode to direct pip commands.

`Final/requirements.txt` remains compatibility-floor metadata for wheel
`Requires-Dist`. `Final/approved-python.lock` is the exact runtime-only
candidate used by the certified installation path. Build, test, and release
tools must never enter that runtime lock.

## Release evidence gate

The filename `approved-python.lock` does not by itself make a release ready.
Treat a newly compiled lock as **provisional** until all of the following
opt-in gates have passed:

- Set `YT_FINAL_LOCK_PYTHON` to the canonical absolute path of the reviewed
  interpreter. The path must already exist as an executable regular file,
  every component must be free of symlinks, junctions, and reparse points,
  and it must resolve to that same file. Bare names and relative paths are
  rejected rather than resolved through `PATH`. On Windows it must be a real
  64-bit `.exe` proven by the operating system, not a batch file or an inert
  file that happens to pass `os.access`. The interpreter must be standard-ABI
  CPython, report the same resolved `sys.executable`, and provide
  `pip==26.1.2` plus `pip-tools==7.6.0`.
- Set `YT_FINAL_VERIFY_LOCK_REGEN=1` to regenerate all four lockfiles with that
  interpreter and compare the generated bytes with the tracked files.
- Set `YT_FINAL_VERIFY_LOCK_WHEELS=1` to check the runtime lock's wheels for
  all six tier-one targets.
- Set `YT_FINAL_VERIFY_NATIVE_LOCK=1` and set `YT_FINAL_NATIVE_TARGET` to the
  current runner's exact label before running
  `test_dependency_locks_install_natively_with_hashes`.

The accepted native target labels are:

```text
windows-x86_64-py311
windows-x86_64-py314
macos-x86_64-py311
macos-x86_64-py314
macos-arm64-py311
macos-arm64-py314
```

The native gate probes `YT_FINAL_LOCK_PYTHON` for CPython identity, the exact
Python version, 64-bit process width, operating system, process architecture,
standard non-free-threaded, non-trace-reference ABI, matching resolved
`sys.executable`,
`pip==26.1.2`, and `pip-tools==7.6.0`. It then uses that verified interpreter
to create a fresh virtual environment for each runtime, build, development,
and release lock. Every Python module launch is isolated and receives the
sanitized environment described above. Every environment must install with
hashes and binary-only policy, pass `pip check`, contain exactly the reviewed
distribution names and versions, and run its direct import or command probe.
A missing or mismatched target label fails rather than silently skipping.

The network preflight
`test_runtime_lock_has_wheels_for_every_tier_one_target` checks Windows x86-64
plus macOS x86-64 and arm64 wheel availability under Python 3.11 and 3.14; it
does not replace native installation evidence.

The cross-target preflight intentionally passes `--no-deps` because the lock
already enumerates the expected closure. That test proves only that every
listed, hash-pinned distribution has a wheel accepted for each requested tag.
It does not re-resolve dependency metadata or certify that the closure works
together. The native `--require-hashes` installs and `pip check` are the
dependency-closure certification.

Do not publish when any matrix target is absent, skipped, or failing.

## License review gate

`bgutil-ytdlp-pot-provider==1.3.1` declares GNU GPLv3 metadata. Keeping it in
the compatibility floor and candidate lock is intentional product behavior,
not a license-compatibility certification. Its inclusion and the release
distribution model require explicit legal/license review before publication;
do not silently remove or substitute it to make the gate pass.

The reviewed PyPI wheel has SHA-256
`e62b21f9b2e4479d59af87a8900387c34892e8d7fdb223f266749a90e0be22de`.
The wheel contains six members. Its metadata has the GPLv3 classifier, no
`License` field, and no member named `LICENSE`, `COPYING`, or `NOTICE`. These
facts are recorded for review and are not legal approval. Publication remains
blocked until the explicit legal/license review is complete.
